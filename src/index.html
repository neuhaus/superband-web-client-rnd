Choose an image; it's cropped to the dial size and encoded automatically — JPEG 4:4:4 when the badge reports dial algorithm 4, otherwise RGB565 — then uploaded over the FitPro dial31 path (or Baji for Baji badges).

Push video / GIF

Loop a short animation on the badge — decoded in the browser to an MJPG AVI and uploaded over the FitPro dial31 path (fileType 1). GIF / WebP / APNG use the browser's image decoder; MP4 / MOV / WebM are sampled at the chosen FPS. The AVI is auto-tuned (JPEG quality, then frame rate) to stay within the size budget — these badges often have well under 1 MB free, and a file that's too big is refused with an out of storage status. The badge is a 1.5" 240×240 panel holding roughly 50 images, 3 videos (each under 5 s) and GIFs.

Faces / videos on the badge

What the badge is storing, read over JieLi RCSP (service ae00). RCSP is auth-gated — the badge ignores commands until a six-step handshake completes, which the tool does automatically on connect.

Stored faces

RCSP

Reads the badge's storage state over authenticated RCSP: connection, free space, the current watch path (/WATCH) and the storage list.

Experimental: raw file access

On BG02 the RCSP browse returns no entries and the name-based read (0x24 op 2) drops the link, so these can't succeed on this firmware — kept for other devices.
